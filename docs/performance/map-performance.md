# 위험지역 지도 표출 성능 비교

2026-11-01에 이미 적용된 최적화의 효과를 측정했습니다. 추가적인 앱 최적화는 적용하지 않았습니다.

## 비교 대상과 조건

- 이전: `e9f0eefcc5a27e6a10c33cb947cce421d7412683`의 `src/app/page.tsx` 마커 생성 로직을 재현했습니다. 모든 장소에 마커를 즉시 등록하고, 장소마다 50px 이미지와 클릭 이벤트를 생성합니다. 클러스터링은 사용하지 않습니다.
- 이후: 현재 `HikingMap.tsx`의 마커 효과를 그대로 추출하고 계측 카운터만 추가했습니다. 화면 주변 선별, 이미지 공유, 캐시, 변경분 일괄 갱신과 클러스터링을 포함합니다.
- 두 방식 모두 같은 최신 데이터 4,870건, 같은 SDK·지도 인스턴스와 중심 좌표를 사용했습니다. 옛 데이터와 새 데이터를 비교한 결과가 아닙니다.
- 브라우저: Chrome 156 계열의 앱 내 브라우저(macOS 사용자 에이전트). CPU·네트워크 제한 없음. 1000 × 600px와 375 × 600px 지도 크기를 별도로 비교했습니다.
- 시작 위치: 월악산 영봉(36.886124, 128.105896), 지도 레벨 6.
- 각 방식 5회 반복하고 실행 순서를 번갈아 배치했습니다. 반복마다 초기화 후 인근 이동·복귀 2회와 레벨 `6 → 8 → 10 → 8 → 6` 확대·축소 4회를 실행했습니다.
- SDK·아이콘을 미리 로드하고 같은 지도 범위의 타일을 예열했습니다. SDK 다운로드와 첫 타일 로딩 시간은 초기 등록 시간에 포함하지 않습니다.
- 2rAF: 조작 시작부터 두 번째 `requestAnimationFrame` 콜백까지의 경과 시간입니다. 타일 다운로드 완료나 실제 화면 표시 완료를 보장하는 지표가 아니며, 실사용 INP·FPS·LCP로 해석할 수 없습니다.
- 초기화는 5개, 이동은 10개, 확대·축소는 20개 표본의 중앙값을 사용했습니다. P95는 확대·축소 20개 표본의 nearest-rank 방식입니다. 표시값은 소수점 한 자리로 반올림하고 변화율은 원본 수치로 계산했습니다.

## 객체·DOM·긴 작업

| 지표 | 데스크톱 이전 → 이후 | 모바일 폭 이전 → 이후 |
| --- | ---: | ---: |
| 초기 개별 마커 이미지 DOM | 4,870 → 2 | 4,870 → 2 |
| 시나리오 중 최대 보유 마커 객체 | 4,870 → 744 | 4,870 → 329 |
| 시나리오 중 최대 개별 마커 이미지 DOM | 4,870 → 9 | 4,870 → 3 |
| 50ms 초과 긴 작업 수 · 5회 합계 | 5 → 5 | 5 → 2 |
| 긴 작업의 50ms 초과분 누적 · 5회 합계(ms) | 3,050 → 269 | 2,984 → 7 |

긴 작업은 Long Tasks API로 수집했습니다. 긴 작업의 초과분 합계는 이 시험 구간에만 해당하며 Lighthouse TBT가 아닙니다. 개별 이미지 DOM 수에는 클러스터의 숫자 요소가 포함되지 않습니다. 캐시 수는 해당 경로의 관측값이며 캐시 상한이나 메모리 사용량(MB)이 아닙니다.

## 해석

- **초기 비용 감소:** 전국 4,870개 마커를 생성·등록하던 작업을 초기 영역의 10개 마커로 줄여 초기 등록 시간이 크게 단축됐습니다. 데이터 건수를 줄이거나 정밀도를 낮춘 결과는 아닙니다.
- **이동 중 부담 감소:** 개별 마커 이미지 DOM과 지도에 등록된 마커 수가 줄어 인근 이동의 2rAF 시간이 감소했습니다.
- **확대·축소의 절충:** 데스크톱의 중앙값은 감소했지만 P95는 60.5ms에서 109.4ms로 증가했습니다. 레벨 10의 넓은 범위를 처음 표시할 때 캐시가 72개에서 744개로 늘어나는 구간에서 약 100ms의 작업이 관측됐습니다. 초기 비용 일부가 최초 영역 확장 시점으로 이동한 것입니다.
- **재사용 효과:** 넓은 범위를 방문한 뒤 되돌아올 때는 새 마커 생성 없이 기존 캐시를 재사용했습니다. 방문 영역이 늘면 캐시도 증가하므로 이 측정만으로 장시간 사용 시 메모리 개선을 단정할 수 없습니다.
- **개별 기법의 기여도:** 이번 비교는 현재 적용된 표출 방식 전체의 효과입니다. 범위 선별·이미지 공유·클러스터링 각각의 단독 개선율을 분리 측정한 결과는 아닙니다.
